# Техническая документация

## 1. Назначение приложения

Приложение разрабатывается по тематике "Оценка камер" и предназначено для оценки качества камеры устройства по фотографии, метаданным снимка и справочной информации о модели камеры или телефона.

Система объединяет два источника данных:

- технический анализ загруженной фотографии;
- справочную оценку устройства из локальной базы камер, сформированной по открытым источникам рейтингов камер.

Результатом работы является итоговая оценка камеры, представленная числом и звездами из 10, а также текстовая аналитика, объясняющая полученный результат.

## 2. Состав проекта

| Файл | Назначение |
| --- | --- |
| `main.py` | Консольный интерфейс, основной пользовательский сценарий, запуск анализа и вывод результата |
| `analyzer.py` | Анализ изображения, расчет метрик качества, извлечение EXIF/RAW-метаданных |
| `database.py` | Работа с SQLite и MS SQL Server, создание таблиц, сохранение и чтение результатов |
| `dxomark_service.py` | Поиск справочной оценки камеры по локальной таблице моделей |
| `config.json` | Настройки подключения к базе данных |
| `photo_analysis.db` | Локальная SQLite-база с результатами анализа и справочными данными |
| `requirements.txt` | Список Python-зависимостей |
| `PhotoGenerator/` | Вспомогательные генераторы тестовых изображений и таблиц |

## 3. Используемые технологии

Приложение написано на Python.

Основные библиотеки:

- `Pillow` - открытие растровых изображений и чтение EXIF;
- `rawpy` - чтение RAW-файлов камер;
- `numpy` - численные расчеты по пиксельным массивам;
- `sqlite3` - локальное хранение данных;
- `pyodbc` - подключение к MS SQL Server;
- `matplotlib`, `pandas`, `scipy`, `opencv-python` - вспомогательные библиотеки для обработки и анализа данных.

## 4. Архитектура решения

Приложение построено как модульная консольная программа.

Основные компоненты:

| Компонент | Роль |
| --- | --- |
| Интерфейс пользователя | Получает путь к фото, выводит отчет и результаты анализа |
| Модуль анализа изображения | Рассчитывает технические метрики снимка |
| Модуль метаданных | Извлекает модель устройства и параметры съемки |
| Справочный модуль | Сопоставляет модель устройства со справочной базой камер |
| Модуль хранения данных | Сохраняет результаты анализа и справочные данные |

Общий поток обработки:

1. Пользователь запускает приложение.
2. Приложение загружает настройки подключения к базе данных.
3. Пользователь выбирает оценку камеры и указывает путь к фотографии.
4. Изображение передается в модуль анализа.
5. Рассчитываются технические метрики снимка.
6. Из файла извлекаются метаданные устройства и параметры съемки.
7. Модель устройства сопоставляется со справочной базой камер.
8. Рассчитывается итоговая оценка камеры.
9. Результат сохраняется в базе данных.
10. Пользователь получает отчет с оценкой и аналитикой.

## 5. Пользовательский сценарий

Основной сценарий работы:

1. Пользователь открывает приложение.
2. На стартовом экране отображается назначение приложения: оценка качества камеры.
3. Пользователь выбирает действие `Хочу оценить камеру`.
4. Приложение просит загрузить фотографию или указать путь к файлу.
5. Приложение анализирует фото и метаданные.
6. Если модель устройства определена автоматически, она используется для поиска в справочной базе.
7. Если модель устройства не определена автоматически, пользователь вводит модель телефона вручную.
8. Приложение формирует итоговый рейтинг камеры.
9. Пользователь получает оценку в формате `0-10`, звезды из 10 и поясняющую аналитику.

## 6. Поддерживаемые форматы изображений

Поддерживаются следующие форматы:

- `.jpg`;
- `.jpeg`;
- `.png`;
- `.bmp`;
- `.tiff`;
- `.dng`;
- `.cr2`;
- `.nef`;
- `.arw`.

Растровые изображения обрабатываются через `Pillow`. RAW-файлы обрабатываются через `rawpy`.

## 7. Извлечение метаданных

Приложение использует метаданные снимка для определения устройства и условий съемки.

Из EXIF/RAW-метаданных извлекаются:

- производитель камеры;
- модель камеры или телефона;
- ISO;
- выдержка;
- диафрагма;
- фокусное расстояние.

Эти данные используются для:

- автоматического определения модели устройства;
- поиска устройства в справочной базе;
- интерпретации технических метрик снимка;
- формирования аналитического текста для пользователя.

## 8. Анализ изображения

Для анализа изображение преобразуется в числовой массив пикселей. Далее рассчитываются технические метрики, отражающие качество снимка и работу камеры в условиях данного кадра.

| Метрика | Назначение |
| --- | --- |
| Резкость | Оценивает детализацию и четкость изображения |
| Шум | Оценивает чистоту изображения и выраженность цифрового шума |
| Динамический диапазон | Оценивает сохранение деталей в светлых и темных областях |
| Экспозиция | Оценивает корректность яркости и наличие пересветов или провалов |
| Цветовой баланс | Оценивает соотношение цветовых каналов |
| Насыщенность | Оценивает выраженность цвета |
| Контраст | Оценивает различимость светлых и темных областей |

Метрики используются как промежуточные показатели для расчета технической оценки загруженного фото.

## 9. Анализ растровых изображений

Для JPEG, PNG, BMP и TIFF используется следующий алгоритм:

1. Файл открывается через `Pillow`.
2. Изображение приводится к RGB.
3. Пиксели преобразуются в массив `numpy`.
4. Рассчитываются резкость, шум, яркость, контраст, насыщенность, динамический диапазон и экспозиция.
5. Из EXIF извлекаются модель устройства и параметры съемки.
6. Формируется словарь результата анализа.

Основные вычисления:

- резкость рассчитывается через дисперсию градиентов по X и Y;
- шум рассчитывается через вариативность яркости;
- яркость рассчитывается как среднее значение пикселей;
- контраст рассчитывается через стандартное отклонение яркости;
- насыщенность рассчитывается по разнице RGB-каналов;
- динамический диапазон оценивается через распределение яркости;
- экспозиция оценивается по доле слишком темных и слишком светлых пикселей.

## 10. Анализ RAW-изображений

Для RAW-файлов приложение использует данные сенсора до финальной JPEG-обработки.

RAW-анализ включает:

- чтение Bayer-массива через `rawpy`;
- расчет резкости по центральной области RAW-данных;
- расчет шума по теневым областям;
- оценку динамического диапазона через отношение сигнала к шуму;
- получение RGB-preview для цветовых и экспозиционных метрик;
- извлечение модели камеры и параметров съемки из RAW-метаданных.

RAW-файлы дают больше технической информации о работе камеры, поэтому их анализ используется как более информативный сценарий для оценки качества устройства.

## 11. Справочная база камер

В приложении используется локальная справочная база моделей камер и телефонов. В текущей структуре таблица содержит:

- идентификатор записи;
- название модели;
- справочный балл камеры.

Справочный балл используется как внешний показатель уровня камеры устройства. Источником данных могут быть открытые рейтинги камер, например DXOMARK и аналогичные базы.

Для сопоставления модели выполняются:

1. поиск точного совпадения;
2. поиск частичного совпадения;
3. нормализация отдельных названий моделей;
4. ручной выбор модели пользователем.

## 12. Сопоставление модели устройства

Модель устройства может поступать из двух источников:

- автоматически из EXIF/RAW-метаданных;
- вручную от пользователя.

Алгоритм сопоставления:

1. Получить исходное название модели.
2. Очистить строку от лишних пробелов и привести к единому регистру.
3. Выполнить поиск в справочной базе.
4. При необходимости применить нормализацию названия.
5. Если найдено несколько подходящих моделей, предложить пользователю выбрать нужную.

Примеры пользовательского ввода:

- `Samsung S23`;
- `Samsung Galaxy S23`;
- `iPhone 15 Pro`;
- `Xiaomi 14 Ultra`.

## 13. Техническая оценка фото

Техническая оценка фото является промежуточной оценкой качества загруженного снимка. Она используется при расчете итогового рейтинга камеры.

Рекомендуемая шкала для промежуточных метрик: `0-10`, где `10` означает лучший результат.

Рекомендуемые веса:

| Компонент | Вес |
| --- | ---: |
| Резкость | 25% |
| Шум | 20% |
| Динамический диапазон | 20% |
| Экспозиция | 15% |
| Цветовой баланс | 10% |
| ISO/выдержка при наличии | 10% |

Итоговая техническая оценка фото:

```text
photo_quality_score =
    sharpness_score * 0.25 +
    noise_score * 0.20 +
    dynamic_range_score * 0.20 +
    exposure_score * 0.15 +
    color_balance_score * 0.10 +
    metadata_score * 0.10
```

## 14. Нормализация справочного рейтинга

Справочный рейтинг камеры приводится к шкале `0-10`.

Для локальной базы может использоваться нормализация по минимальному и максимальному значениям:

```text
reference_score_10 = 10 * (score - min_score) / (max_score - min_score)
```

После расчета значение ограничивается диапазоном:

```text
reference_score_10 = clamp(reference_score_10, 0, 10)
```

Такой подход позволяет сравнивать устройства внутри общей справочной базы и выводить результат в понятной пользователю шкале.

## 15. Итоговая оценка камеры

Итоговая оценка камеры объединяет справочный рейтинг устройства и техническую оценку загруженного фото.

Если модель найдена в справочной базе:

```text
base = reference_score_10
photo_adjustment = (photo_quality_score - 7.0) * 0.25
camera_quality_score = clamp(base + photo_adjustment, base - 1.0, base + 0.7)
```

Если модель устройства не найдена в справочной базе, итоговая оценка строится по технической оценке фото:

```text
camera_quality_score = photo_quality_score
```

Итоговая оценка отображается:

- числом от `0` до `10`;
- звездами из 10;
- текстовой аналитикой.

## 16. Уровень доверия к оценке

Для результата рассчитывается уровень доверия.

| Уровень | Условия |
| --- | --- |
| `high` | Модель определена по метаданным и найдена в справочной базе |
| `medium` | Модель введена вручную и найдена в справочной базе |
| `low` | Справочная модель не найдена, используется анализ фото |

Уровень доверия помогает пользователю понять, на каких данных основан итоговый результат.

## 17. Хранение данных

Приложение поддерживает два режима хранения:

- SQLite;
- MS SQL Server.

Для локального тестирования используется SQLite.

Пример конфигурации:

```json
{
  "database": {
    "type": "sqlite",
    "sqlite": {
      "db_path": "photo_analysis.db"
    },
    "mssql": {}
  }
}
```

Основные таблицы:

| Таблица | Назначение |
| --- | --- |
| `analysis_results` | Результаты анализа фотографий |
| `dxomark` | Справочные оценки моделей устройств |
| `categories` | Пользовательские категории |
| `photo_categories` | Связь фотографий с категориями |

Основные группы данных результата:

- сведения о файле;
- технические метрики изображения;
- EXIF/RAW-метаданные;
- модель камеры;
- справочная оценка устройства;
- пользовательская оценка и заметки;
- аналитический результат.

## 19. Запуск приложения

Для запуска приложения необходимо открыть терминал в папке проекта и выполнить:

```powershell
.\.local-venv\Scripts\python.exe main.py
```

Если виртуальное окружение отсутствует, его можно создать и установить зависимости:

```powershell
python -m venv .local-venv
.\.local-venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 20. Итоговая логика работы

Общая логика приложения:

```text
Фото пользователя
→ извлечение метаданных
→ определение модели устройства
→ поиск модели в справочной базе
→ анализ технических метрик снимка
→ расчет оценки фото
→ расчет итоговой оценки камеры
→ вывод рейтинга в звездах и аналитики
```

Такой сценарий делает приложение удобным для финального тестирования другими студентами и соответствует тематике лабораторной работы "Оценка камер".
