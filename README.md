## 🎯 Назначение приложения

Приложение предназначено для предварительной оценки качества камеры устройства по фотографии, метаданным снимка и справочной информации о модели камеры или телефона.

В проекте предусмотрены два варианта работы:

- консольная версия;
- графический интерфейс.

---

# 1. Состав проекта

| Файл / модуль        | Назначение                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `main.py`            | Консольный интерфейс, основное меню, запуск анализа, просмотр списка, поиск, оценка, статистика, категории и удаление записей                     |
| `gui_app.py`         | Графический интерфейс с загрузкой фото, вкладками результатов, метрик, информации о камере, истории анализов и настройками базы данных            |
| `analyzer.py`        | Анализ изображения, расчёт резкости, шума, динамического диапазона, яркости, контраста, насыщенности и экспозиции, извлечение EXIF/RAW-метаданных |
| `database.py`        | Работа с SQLite и MS SQL Server, сохранение анализов, поиск, статистика, категории и связь фото с категориями                                     |
| `dxomark_service.py` | Поиск справочной оценки камеры по модели устройства в локальной базе DxOMark                                                                      |
| `config.json`        | Файл настроек подключения к базе данных                                                                                                           |
| `photo_analysis.db`  | Локальная база данных SQLite                                                                                                                      |
| `requirements.txt`   | Список Python-зависимостей                                                                                                                        |

---

# 2. Системные требования и подготовка

* Установленный Python.
* Наличие зависимостей из файла `requirements.txt`.
* Для RAW-файлов желательно установленное библиотечное окружение с поддержкой `rawpy`.
* Для режима MS SQL Server — доступ к серверу и библиотека `pyodbc`.

> Если файл `config.json` отсутствует, приложение создаст его автоматически и по умолчанию будет использовать SQLite.

# 4. Консольная версия

Главное меню в консольной версии содержит следующие пункты:

1. Анализировать новое фото.
2. Показать все фото.
3. Поиск по фото.
4. Оценить фото.
5. Показать статистику.
6. Добавить категорию.
7. Удалить фото из БД.
8. Сменить БД.
9. Выход.

---

## 4.1. Анализ новой фотографии

1. Запустите пункт **«Анализировать новое фото»**.
2. Введите полный путь к файлу изображения.
3. Дождитесь завершения обработки.
4. Приложение рассчитает метрики качества и попробует определить камеру по метаданным.
5. Если модель устройства найдена, будет выполнен поиск DxOMark-оценки в локальной базе.
6. Если модель не найдена автоматически, можно выбрать её вручную из списка моделей базы.

### Что учитывается при анализе

* резкость;
* уровень шума;
* динамический диапазон;
* яркость;
* контраст;
* насыщенность;
* экспозиция;
* метаданные камеры:

  * производитель;
  * модель;
  * ISO;
  * выдержка;
  * диафрагма;
  * фокусное расстояние.

### Поддерживаемые форматы

* `.jpg`
* `.jpeg`
* `.png`
* `.bmp`
* `.tiff`
* `.dng`
* `.cr2`
* `.nef`
* `.arw`

---

## 4.2. Просмотр списка фотографий

Пункт **«Показать все фото»** выводит таблицу сохранённых анализов с:

* ID;
* именем файла;
* моделью камеры;
* общей оценкой;
* DxO-оценкой;
* основными метриками качества.

---

## 4.3. Поиск фотографий

Пункт **«Поиск по фото»** позволяет найти записи по:

* фрагменту имени файла;
* модели камеры;
* тегам;
* другим данным, сохранённым в базе.

---

## 4.4. Оценка фото пользователем

В пункте **«Оценить фото»** можно:

* выбрать запись по ID;
* задать личную оценку от `1` до `5`;
* добавить заметки;
* добавить теги.

Эти данные сохраняются отдельно от автоматической оценки качества.

---

## 4.5. Статистика

Раздел **«Показать статистику»** выводит:

* общее количество фотографий;
* среднюю оценку;
* среднюю резкость;
* средний уровень шума;
* среднюю пользовательскую оценку;
* список наиболее часто встречающихся моделей камер.

---

## 4.6. Категории

В пункте **«Добавить категорию»** создаётся новая категория.

При необходимости к ней можно сразу привязать фотографию по ID.

---

## 4.7. Удаление записи

Пункт **«Удалить фото из БД»** удаляет выбранную запись после подтверждения пользователя.

---

## 4.8. Смена базы данных

Пункт **«Сменить БД»** позволяет переключиться между:

* SQLite;
* MS SQL Server.

Параметры подключения сохраняются в `config.json`.

# 5. Графический интерфейс

Графическая версия приложения построена на `customtkinter` и предназначена для более удобной работы с анализом фотографий.

## Основные элементы интерфейса

* **Кнопка «Загрузить файл»** — выбор изображения на диске.
* **Кнопка «АНАЛИЗИРОВАТЬ»** — запуск вычисления метрик.
* **Панель предпросмотра** — отображение загруженного изображения.
* **Вкладка «Результаты анализа»** — итоговая оценка и рекомендации.
* **Вкладка «Детальные метрики»** — резкость, шум, динамический диапазон, яркость, контраст, насыщенность и экспозиция.
* **Вкладка «Информация о камере»** — данные о модели, производителе и метаданных снимка.
* **Вкладка «История анализов»** — список последних результатов.
* **Кнопка «Настройки БД»** — переключение типа базы данных.

---

## 5.1. Порядок работы в GUI

1. Откройте `gui_app.py`.
2. Нажмите **«Загрузить файл»** и выберите фотографию.
3. Нажмите **«АНАЛИЗИРОВАТЬ»**.
4. Просмотрите итоговую оценку во вкладке результатов.
5. Перейдите к детальным метрикам и информации о камере при необходимости.
6. Откройте историю анализов, чтобы посмотреть предыдущие результаты.

# 6. Как интерпретировать результаты

Общая оценка формируется на основе набора технических признаков изображения.

В расчёт входят:

* резкость;
* шум;
* динамический диапазон;
* яркость;
* насыщенность;
* правильность экспозиции.

Для RAW-файлов используется отдельная логика обработки с учётом сырых байер-данных.

Если модель камеры найдена в базе DxOMark, приложение дополнительно показывает справочную оценку. Это помогает сопоставить результат анализа снимка с известной моделью устройства.

---

# 7. Форматы файлов и особенности обработки

* Обычные изображения обрабатываются через `Pillow` и `NumPy`.
* RAW-файлы `DNG`, `CR2`, `NEF` и `ARW` обрабатываются через `rawpy`, если библиотека установлена.
* Если `rawpy` отсутствует, RAW-файл будет обработан как обычное изображение.
* Метаданные EXIF используются для определения модели устройства и параметров съёмки.

---

# 8. Работа с базой данных

Приложение может работать с:

* локальной SQLite-базой;
* MS SQL Server.

При запуске читается конфигурация из `config.json`, а при отсутствии файла используются безопасные значения по умолчанию.

## База данных хранит

* результаты анализа изображений;
* пользовательские оценки, заметки и теги;
* категории и привязку фото к категориям;
* справочную таблицу моделей DxOMark.

---

# 9. Ограничения и рекомендации

* Для корректной работы лучше использовать фотографии, сделанные камерой или смартфоном с сохранёнными метаданными.
* Если модель не определяется автоматически, её можно выбрать вручную только из списка, который есть в локальной базе DxOMark.
* Качество оценки зависит от исходного изображения: слишком маленькие, сильно сжатые или повреждённые файлы могут дать менее точный результат.
* При подключении к MS SQL Server нужно проверить корректность:

  * сервера;
  * порта;
  * имени базы;
  * учётных данных.
